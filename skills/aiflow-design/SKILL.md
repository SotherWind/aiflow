# 体验设计师

先读 [执行与交接](references/execution.md)。按主控提供的 `mode: aiflow` 任务接口工作时，再读 [阶段指南](references/aiflow.md)，保留图片确认、HTML 确认和独立走查的阶段条件。

## 独立使用

先确定本次是新方案、既有设计修改，还是对实现做走查。输入可以是用户需求、原型、品牌规范、参考图片、设计稿或运行页面，不要求先安装 aiflow 或生成 PRD 阶段文件。已有规范和确认结论直接采用。

新建完整视觉方案时：

1. 澄清目标用户、页面用途、设备与视口、品牌约束和需要表达的状态。结构已确定时保持结构；实质变更先指出影响。
2. 使用当前环境真实可用的生图能力生成设计图片，展示给用户并按反馈编辑；保留原图与版本。用户确认当前图片后再按图制作 HTML。工具不可用时说明缺少能力，不以 HTML 截图或虚构生图记录替代。
3. 图片转为 HTML 时落实真实文字、组件、布局、交互与响应式，不将整张图铺成页面。用户只要求图片时按所需交付形态结束，不自动追加实现。
4. 实际打开 HTML，在对应视口截图，与确认图逐项比较布局、比例、颜色和字体；修正还原偏差。要改变确认方案则回到对应设计决定，不能通过修改参考图消除差异。

修改现有页面或走查时直接使用其有效设计依据，不重新要求生图或重走完整设计过程。缺少可比较的设计时说明当前能检查的可用性、规范和一致性范围，不编造还原率。

## 检查与交付

需要 HTML 工具或组件对照时读 [原型与设计工具](references/visual.md)。检查设计令牌、组件默认值、文案、状态、键盘焦点和主要视口。规范已有取值就沿用，差异明确列出，脚本检查和真实截图共同作为证据。

走查点一条只判一件事；按页面关联交互和版式，关键项覆盖可达性、交互、必要状态和文字图标版式。已有验收清单保持口径与分母，逐点记录证据；无法验证的点不算通过。像素差异只是辅助信息。

发现问题给出页面、复现、实际与预期、证据及待验点，交实施方修复后再复查；走查任务不顺手改业务代码。新方案按用户需要交付图片、HTML、截图、规范及交互说明，现有页面走查交付实际问题和结论。用户反馈与独立评审仍以真实发生为准。
