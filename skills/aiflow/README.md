# aiflow · 上手

一套把需求推到上线的流程。七个角色、十个阶段、两条硬门禁。

配套阅读：`SKILL.md`（规范）、`references/`（规则）、`experts/`（角色）、`templates/`（记录格式）。

## 五分钟上手

```
/aiflow 做一个设备巡检工单，班组长派单、执行人提交、班组长验收，超时自动升级
```

然后：

1. 首次激活会创建 `.aiflow/`、初始化 `state.yaml` 和阶段 0 模板；已有目录只续跑，不覆盖。
2. **它会先停住**，给你切好的纵切 + 最多 3 个开工阻塞问题。答完才进下一阶段。
3. `/aiflow 继续` 逐阶段推进。**一次只推一格**，不要指望它一口气跑完。
4. 每个阶段收尾，跑一次漂移检查：

```
python "<本 skill 目录>/scripts/check.py" "<项目目录>"
```

5. `/aiflow 状态` 随时看进度、待决策、未关闭缺陷。

## 第一次跑，你会看到什么

阶段 0 不会给你方案，只会给你三样东西：

- 一个明确的边界：`本轮做：X ｜ 本轮不做：Y、Z、W`
- 一份风险线索（并发写入 / 数值精度 / 批处理），**不下技术结论**
- 最多 3 个"不问清就没法定数据模型"的问题；没有就明确写「无」

这是有意的。一句话需求直接出代码，得到的一定是玩具。

## 它给你什么，不给你什么

**给**：可运行的骨架、数据模型、接口实现、单测、端到端用例、发布与回滚方案，以及十一份可追溯的留档。

**不给**：生产级权限体系、高并发调优、安全审计、第三方系统对接、UI 设计、业务决策。

最后一条最关键：**它不替你做业务判断**。所有"该用哪种口径""该不该允许"的问题，它都会停下来问你。让 AI 替你定业务规则，等于把一个错误埋进数据模型，后面每个阶段都会忠实地实现它。

## 常见问题

**一句话能直接出代码吗？**
不能。一句话只能进阶段 0，产出的是边界和问题清单。要代码，得走完前五个阶段。

**必须十个阶段都跑吗？**
不必。小改动可以 `/aiflow 跳到 3`，但会先检查前一阶段的留档物在不在。跳阶段不等于跳留档。

**一个人用行吗？**
行，但开发和测试会由同一个模型扮演。这时候要靠三样东西补：待验点必须写"怎么验会失败"、测试只照验收标准走、断点日志记下每次"测试没抓到但后来暴露了"的记录。详见 `SKILL.md` §八。

**需求变了怎么办？**
从事实源改，不在下游产物里改。规则见 `references/change.md`。

**跑完之后呢？**
归档 `.aiflow/` 整个目录。下次同类项目，把 `facts.md` 当起点改，比从零开始省一半时间。

## 目录

```
SKILL.md              总控：阶段 / 角色 / 门禁 / 决策点 / 漂移控制
references/
  facts-source.md     事实源规则（只追加、编号、引用）
  gates.md            每阶段门禁 + 清零门禁 + 上线门禁
  breakpoints.md      六条断点自查 + 日志模板
  change.md           需求变更的传播规则
experts/              七个角色，各含「做什么 / 自检 / 常见失败 / 提问边界」
  analyst pm architect fe be tester operator
templates/            十二份初始文件（含 state；架构方案没有模板，由 PRD 推导）
scripts/
  check.py            漂移检查：漏 / 编 / 状态一致 / 门禁
tests/
  test_check.py       正常放行与假绿反例回归测试
```

维护本 skill 后运行：

```
python "<本 skill 目录>/tests/test_check.py"
```
