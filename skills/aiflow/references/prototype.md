# 原型图规范

适用：产品经理在阶段 2 出的产品原型图。体验设计师在阶段 3 以它为输入出设计稿，所以原型图要让设计师一眼看懂结构、组件、内容和交互。

## 一、做到中保真

低保真（灰框加文字）只能定页面结构，交给设计师不够：组件类型、信息层级、页面密度都看不出来，设计师只能重新猜。高保真（定好品牌视觉）又会让评审讨论颜色而不是流程，还会替设计师预设视觉。所以原型图做到**中保真**：

| 维度 | 原型图（产品经理） | 设计稿（体验设计师） |
|---|---|---|
| 结构与布局 | 定：页面框架、区域划分、栅格、信息层级 | 沿用；要改结构，回到原型评审 |
| 组件 | 定：用哪种组件（输入框、下拉、单选、复选、表格、标签、弹窗、抽屉、时间轴、步骤条） | 定组件的视觉样式 |
| 内容 | 真实文案和贴近真实的数据，不用「xxx」「示例文字」 | 微调文案长度和语气 |
| 颜色 | 组件库默认样式 + 功能色（主操作、成功、警告、错误、状态标签） | 品牌主色和配色方案 |
| 字体与间距 | 组件库默认的字号层级，8 的倍数间距 | 精确字号、行高、间距 |
| 图形 | 只用组件库自带的图标和空状态占位，不画插画 | 图标风格、插画、品牌元素 |
| 交互 | 页面之间可点击跳转，每个状态都画出来 | 动效、过渡、微交互 |

> 「品牌视觉留给设计稿」的前提是规范还没定。项目已有设计规范时，原型直接用规范的令牌和组件，设计稿按规范补齐细节，不另起视觉。

## 二、用哪套组件库

1. 先定设计规范：按 `references/design-system.md` 找项目或公司已有的规范，记进 `.aiflow/design-system.md`。有规范就用它的令牌和组件。
2. 没有规范时，B 端 Web 默认用 **Ant Design 默认主题**的样式。它是国内中后台最常见的组件库，墨刀、即时设计、MasterGo、Figma 都有现成的组件包，设计师和前端都能直接对上。
3. HTML 原型直接用本 skill 的 `templates/prototype-kit/`：一套照 Ant Design 默认风格写的样式包。`build.py` 构建时把样式内联进页面，并用 `.aiflow/design-system.md` 的令牌覆盖默认值。
4. 没有规范时，原型用 Ant Design 的样式不等于前端必须用它，阶段 4 的架构师按 `references/tech-stack.md` 提出选型，经用户确认后锁定。规范声明了组件库时，架构师的选型要能用它。

## 三、交付物结构

1. **总览**：修订记录、页面流程图（哪个角色从哪个页面进来、怎么跳转）、页面清单（每页服务哪几条 A）
2. **全局说明**：页面框架、列表规则（默认排序、分页、空 / 加载 / 出错）、表单规则（必填标记、校验时机、错误提示位置、防重复提交）、操作反馈、时间格式、敏感信息怎么显示、权限、状态与颜色对照
3. **角色 × 状态矩阵**：每个状态下，每个角色能看到什么、能做什么
4. **每个页面**：主状态的完整画面 + 编号标注 + 其他状态

## 四、标注怎么写

- **标注层和界面层分开**：标注用黄色圆圈数字，不混进界面配色。
- **一个编号说清一个元素**：什么时候显示、字段规则（必填、格式、来源）、点了之后怎么样、谁能看谁能操作、失败时提示什么。末尾写依据的 R / A 编号。
- **全局规则写进全局说明**，页面里不重复写。

## 五、状态要画全

每页至少有：默认、空、加载、出错、无权限。不适用的写明原因（例如「公网页面无需登录，没有无权限状态」）。再加上这一页特有的状态：弹窗、冲突提示、次数上限、已关闭等。

## 六、交付前自查

- [ ] 文案和数据是真实的，没有「xxx」「示例文字」
- [ ] 每个控件的类型都明确，不是一个灰框里写字
- [ ] 主操作、次操作、危险操作的按钮层级分得清
- [ ] 状态标签用语义类（`tag primary / success / warning / danger / info`），每个状态用哪种类型写在 design-system.md，所有页面一致
- [ ] 有设计规范时，原型用的是 `.aiflow/design-system.md` 的令牌，构建输出列出的覆盖项和规范一致
- [ ] 页面里没有用行内样式写死颜色，构建时没有「写死了颜色」的提示
- [ ] 每个可点击的元素都能跳到下一个画面或状态
- [ ] 标注覆盖了全部字段规则、显示条件和权限，每条都写了 R / A
- [ ] 页面里没有 PRD 之外的功能（断点 B7）
- [ ] 每个页面运行 `layout-check.js` 和 `spec-check.js`，没有报出文字或图标偏移、换行、溢出（截图里肉眼看不出 4–7px 的偏移），也没有规范外的颜色、字号、圆角、控件高度
- [ ] 文件不依赖外部样式和脚本，导出了 PNG，用用户的查看方式打开过一次

## 七、依据

- 保真度按交互、视觉、内容分维度看，可以混搭：[NN/g · UX Prototypes: Low Fidelity vs. High Fidelity](https://www.nngroup.com/articles/ux-prototype-hi-lo-fidelity/)
- 中保真：真实文案、确定的布局和层级、明确的控件类型、准确的表格字段、大量标注，不要求品牌色和精确尺寸：[Moqups · Mid-Fidelity Wireframes](https://moqups.com/blog/mid-fidelity-wireframes/)
- 低保真只定布局，中保真已有真实文案和确定的栅格：[低、中高保真原型](https://www.cnblogs.com/htblog/p/16363282.html)
- B 端后台原型的常见结构与重点：[B 端后台管理系统原型素材](https://www.cnblogs.com/PMEcho/p/19470968)
- Ant Design 的墨刀、即时设计、MasterGo、Figma 组件包：[Ant Design 设计资源](https://ant.design/docs/resources-cn)
