# 项目规范、技术栈与证据

本文件由 `scripts/bundle_skills.py` 从 `shared/development.md` 分发。

开发、架构、测试和发布前先读项目实际约束：仓库说明、依赖与锁文件、构建命令、接口和现有实现。已有框架、版本和规范优先沿用；用户明确指定的要求不能被个人偏好替换。

开发规范按显式提供、项目默认、团队默认查找。项目可采用 `.aiflow/frontend-standards.md`、`.aiflow/backend-standards.md`；团队可用 `~/.aiflow/` 下同名文件，也可沿用仓库已有规范。没有这些可选文件时读现有代码，不要求用户补一套 aiflow 配置。

已指定规范应读取全文，实际适用的条目落实到实现或验证。规范与现状、契约、设计或用户要求冲突时，先指出具体冲突和影响；已有授权能解决的工程细节自行处理，新的实质取舍再请用户决定。修复前重读受影响的规范，不以旧摘要代替。

选择新技术时说明候选组合、版本依据和取舍；查证兼容性后再建议，不把期望版本当成已安装版本。任务没有要求换栈时保留当前选型。需要更换已确认方案或超出其版本约束时重新确认。

验证以真实执行为依据：记录命令、环境、退出码、相关结果与产物。测试范围由改动及其影响推导；未运行、不支持和失败分别说明。修复问题的实现和独立复测证据分开保留，不能改断言来掩盖实现错误。

在 aiflow 协作中，选型锁定、规范路径、指纹和开发记录还要遵循主控提供的 `flow_root/references/development-standards.md` 与 `flow_root/references/tech-stack.md`；状态仍交主控更新。
