# 前端开发规范示例

这是一份可删改的规则示例。采用前按项目实际情况调整；它不代表本项目已经确认了这些规则，也不包含已执行的检查结果。

## 适用范围

- 适用对象：使用 TypeScript 的浏览器前端，新功能和缺陷修复均适用。
- 框架与版本：沿用项目已确认的技术栈，本规范不指定或更换框架。
- 来源与版本：项目采用的前端开发约定 v1，初稿参考 aiflow 随包示例。
- 视觉依据：以项目设计规范和确认设计稿为准；本文件约束代码组织与行为。

## 开发约定

| 编号 | 规则 | 如何检查 |
| --- | --- | --- |
| FE-01 | 现有目录结构继续沿用。新增业务功能放在同一业务目录内，页面组件组织展示与交互，接口访问集中在项目已有请求层；共享组件不直接依赖具体业务接口。 | 检查本次新增文件的职责、导入关系和接口调用位置。 |
| FE-02 | 请求参数和响应字段有明确类型，按实际接口契约区分必填、可选和可空；接口响应在请求边界处理，不把未经校验的数据强转成业务类型。 | 运行项目已有类型检查，并对照本批接口文档核对字段。 |
| FE-03 | 列表和详情覆盖加载、成功、空数据、失败状态；请求失败提供用户可理解的提示和可重试入口。筛选变化后的旧响应不得覆盖新结果。 | 在真实页面验证空结果、断网、慢请求与快速切换筛选。 |
| FE-04 | 表单错误放在对应字段附近；提交中防止重复触发，失败后保留可继续修改的输入。权限拒绝以服务端结果为准，不把隐藏按钮当作权限校验。 | 验证连续点击提交、字段错误、服务端拒绝和再次提交。 |
| FE-05 | 业务页面通过项目统一主题或设计令牌使用颜色、字号、圆角；新增视觉取值先核对设计依据。图标按钮有可访问名称，键盘焦点可见。 | 对照确认设计检查页面样式，使用键盘走一遍相关操作。 |
| FE-06 | 本次改动运行项目已有的格式、静态检查、类型检查和相关行为测试；没有某项脚本时如实说明，并采用能验证相关行为的现有方法。 | 交付中记录实际命令、结果、页面证据及尚未覆盖的情况。 |

## 类型约定举例

下面仅演示如何表达字段含义；实际字段仍以已确认接口为准。

```ts
type RecordSummary = {
  id: string;
  title: string;
  ownerName: string | null; // 已知没有负责人时为 null
  updatedAt: string;       // 按接口约定格式返回的时间文本
};
```

可选属性、空字符串和 `null` 不相互替换。例如契约保证 `ownerName` 一定返回时，不因为页面暂时不用就改成可选属性。

## 交付与变更

交付说明引用适用规则编号，附实际检查证据和未满足项。全流程执行时由日志写入者汇总到 `06-dev-log.md` 的「开发规范执行」；独立角色任务使用项目现有交付记录即可。

规则与已有契约、设计或技术栈冲突时，列出具体差异和影响，按本轮已确认决定处理；新取舍交给用户决定。仅修改受影响的规则，保留原始依据。
