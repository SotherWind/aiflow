# 后端开发规范示例

这是一份可删改的规则示例。采用前按项目实际情况调整；它不代表本项目已经确认了这些规则，也不包含已执行的检查结果。

## 适用范围

- 适用对象：HTTP JSON 接口、数据访问和后台任务；BE 与 JOB 共用。
- 语言、框架与数据库：沿用项目已确认技术栈，本规范不新增技术选型。
- 来源与版本：项目采用的后端开发约定 v1，初稿参考 aiflow 随包示例。
- 接口依据：已有接口保持兼容；下文的分页和错误结构仅供尚未约定结构的新接口参考。

## 开发约定

| 编号 | 规则 | 如何检查 |
| --- | --- | --- |
| BE-01 | 沿用项目已有分层。入口负责请求解析与响应，业务层落实业务规则，数据访问集中在项目已有数据层；后台任务调用相同业务能力。 | 检查本次入口、业务规则和数据写入之间的调用关系。 |
| BE-02 | 服务端校验输入、身份、数据权限与当前状态。校验失败时不产生部分业务写入；错误按已确认契约返回。 | 验证非法字段、越权访问、资源不存在和非法状态操作。 |
| BE-03 | 必须共同成功的写入使用项目支持的事务边界。涉及重复请求或并发修改时，明确幂等或冲突处理规则并验证；不向无此需求的操作统一加入锁。 | 对相关写入验证重复提交、冲突和中途失败后的实际数据。 |
| BE-04 | 分页、时间、空值和错误结构按接口契约统一。兼容已有消费者；行为或响应变化同步接口文档和交付版本。 | 对照接口文档核对实际响应，并记录受影响的调用方。 |
| BE-05 | 日志保留定位所需的请求或任务标识、操作和错误原因；响应和日志不包含密码、令牌或数据库连接秘密。配置从项目已有配置机制读取。 | 检查本次新增日志、异常处理、配置示例和错误响应。 |
| BE-06 | JOB 写清触发方式、处理范围、重跑行为、失败记录和恢复办法。成功启动进程不等于任务处理成功。 | 验证实际处理结果、重复运行和失败后恢复路径。 |
| BE-07 | 使用项目实际测试工具验证正常、拒绝和异常行为。交付给前端的接口包含可调用环境、当前版本、请求响应、错误、权限和测试准备。 | 记录实际测试命令与结果；交接后由前端验证真实调用结果。 |

## 新接口的格式示例

本例约定分页从第 1 页开始，空列表保留分页结构；实际项目采用前先与前端确认字段和含义：

```json
{
  "items": [],
  "page": 1,
  "pageSize": 20,
  "total": 0
}
```

本例的校验错误返回稳定的业务代码、可读说明和排查标识；错误对应的 HTTP 状态也需写入接口文档：

```json
{
  "code": "VALIDATION_FAILED",
  "message": "名称不能为空",
  "requestId": "example-request-001"
}
```

`requestId` 是示例值，真实请求使用实际链路标识。原始异常堆栈留在受控服务端日志中，不直接作为用户提示。

## 交付与变更

交付说明引用适用规则编号，附实际检查证据和未满足项。全流程执行时由日志写入者汇总到 `06-dev-log.md` 的「开发规范执行」，JOB 使用 BE 行；独立角色任务使用项目现有记录即可。

规则与已有契约、数据或技术栈冲突时，说明兼容性及影响，再按本轮已确认决定处理。数据迁移与部署权限根据实际任务另行确定，本规范本身不授权执行发布操作。
